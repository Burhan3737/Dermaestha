## Summary
Root cause: ESLint was upgraded to v9 (installed 9.39.4), whose default config format is flat `eslint.config.js`; the repo root still only had the legacy `.eslintrc.json`, which v9 ignores. So `eslint .` (the `npm run lint` script) crashed with "couldn't find eslint.config" (exit 2), and the editor's ESLint extension flagged every non-`client/` file with that same error (red = error severity, not lint warnings). `client/` was unaffected because it already has its own flat config + its own ESLint v10. Fix (user chose "one unified root config"): add a single root flat `eslint.config.js` covering Node (server/shared/prisma/root) + React (client), delete the legacy `.eslintrc.json` and the now-redundant `client/eslint.config.js`, and align ESLint to one major (v10).

## Context / why
User reported "lint seems broken" and every opened file showing red (error) markers. Investigation confirmed the ESLint 9 flat-config migration was never completed at the repo root.
